# Gemini API の用途

このドキュメントでは、mealcopilot（ミルコ）アプリケーションにおけるGemini APIの用途と実装について説明します。

## 概要

本アプリケーションでは、Google の Gemini API（生成AI）を活用して、食品の自動カテゴリ分類を実現しています。Gemini APIは自然言語処理と生成AIの能力を持ち、ユーザー入力された食品名から適切なカテゴリを推論します。

## 使用モデル

- **モデル**: `gemini-2.0-flash`
- **エンドポイント**: `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent`

Gemini 2.0 Flashは、高速かつ効率的な生成AIモデルで、シンプルなテキスト分類タスクに最適です。

## 現在の用途

### 1. 食品カテゴリの自動分類

**実装場所**: `/lambda/functions/food-category/index.ts`

#### 機能概要
ユーザーが新しい食品を在庫に追加する際、食品名を入力するだけで自動的に適切なカテゴリに分類されます。これにより、ユーザーは手動でカテゴリを選択する手間が省け、在庫管理がより効率的になります。

#### カテゴリリスト
以下の8つのカテゴリから自動的に分類されます：
- 野菜
- 果物
- 肉類
- 魚介類
- 乳製品
- 穀物
- 調味料
- その他

#### 実装の詳細

**リクエスト例**:
```
GET /food-category?foodName=トマト
```

**プロンプト設計**:
```javascript
あなたは食品カテゴリ分類AIです。以下の食品がどのカテゴリに属するか、以下のリストから一つだけ選んでください。

カテゴリリスト:
- 野菜
- 果物
- 肉類
- 魚介類
- 乳製品
- 穀物
- 調味料
- その他

食品名: ${foodName}

カテゴリ名のみを出力してください。説明は不要です。
```

**生成パラメータ**:
- `temperature: 0.0` - 決定論的な出力（毎回同じ結果）
- `maxOutputTokens: 10` - カテゴリ名のみを返すため、短い出力に制限

**レスポンス例**:
```json
{
  "foodName": "トマト",
  "category": "野菜"
}
```

#### メリット
1. **ユーザビリティの向上**: 手動でカテゴリを選択する必要がなく、入力が簡単
2. **精度の高い分類**: AIによる自然言語理解により、さまざまな食品名の表記に対応
3. **一貫性のある管理**: 自動分類により、ユーザー間でのカテゴリ分類のばらつきを防止

## 技術仕様

### API認証
- API キーは環境変数 `GEMINI_API_KEY` として設定
- AWS Lambda の環境変数として管理され、GitHub Actions でデプロイ時に自動設定

### エラーハンドリング
1. **API キー未設定**: サーバー設定エラーとして 500 を返す
2. **API呼び出しエラー**: Gemini APIからのエラーレスポンスをそのまま返す
3. **予期しないレスポンス形式**: 500 エラーと適切なエラーメッセージを返す
4. **無効なカテゴリ**: 有効なカテゴリに含まれない場合は「その他」に分類

### パフォーマンス最適化
- **軽量モデル使用**: Gemini 2.0 Flashを使用し、レスポンス時間を短縮
- **出力トークン制限**: 最大10トークンに制限し、不要な生成を防止
- **温度設定**: temperature 0.0 で決定論的な動作を保証

## 将来的な拡張案

### 1. レシピ提案機能での活用（計画中）
現在、レシピ提案機能ではモックデータを使用していますが、将来的にはGemini APIを活用して以下を実現する予定です：

#### 機能案
- **在庫ベースのレシピ生成**: 現在の在庫食材を基に、オリジナルのレシピを生成
- **賞味期限を考慮**: 期限が近い食材を優先的に使用するレシピの提案
- **栄養バランス最適化**: ユーザーの栄養目標に合わせたレシピの生成
- **調理時間・難易度の調整**: ユーザーの要望に応じた難易度のレシピを提案

#### 想定されるプロンプト例
```
以下の食材を使って、30分以内で作れる簡単なレシピを提案してください。
特に賞味期限が近い食材（★マーク）を優先的に使用してください。

利用可能な食材:
- トマト ★（賞味期限: 2026-02-16）
- 玉ねぎ
- 鶏もも肉 ★（賞味期限: 2026-02-15）
- パスタ
- オリーブオイル

レシピには以下を含めてください:
1. レシピ名
2. 調理時間
3. 難易度
4. 材料と分量
5. 作り方（ステップごと）
6. 栄養情報（カロリー、タンパク質、炭水化物、脂質）
```

### 2. 栄養情報の自動取得
食品成分表にない食品や、調理済み料理の栄養情報をGemini APIで推定

### 3. 食事記録の自動分析
ユーザーの食事記録から栄養バランスの分析と改善提案を生成

### 4. 多言語対応
Gemini APIの多言語能力を活用し、海外の食品名やレシピにも対応

## セキュリティ考慮事項

1. **API キーの管理**: 
   - GitHub Secrets で管理
   - Lambda 環境変数として設定
   - コードには直接記述しない

2. **レート制限**:
   - 現時点では制限を実装していないが、本番環境では適切なレート制限を実装すべき

3. **入力検証**:
   - 食品名の長さ制限
   - 不適切な入力のフィルタリング（実装推奨）

## コスト管理

Gemini APIの使用コストを最小限に抑えるための工夫：

1. **軽量モデルの使用**: Gemini 2.0 Flash（コスト効率的）
2. **出力トークン制限**: maxOutputTokens を10に設定
3. **キャッシング**: 同じ食品名の分類結果をキャッシュする仕組みの導入を検討
